# Operations

Operational docs cover how to keep runtime behavior understandable and safe as
you iterate.

Use this section when you are diagnosing issues, validating changes, or
tightening feedback loops.

These pages are intended to be used together: debugging for reproduction,
observability/logging for signal quality, and testing to lock fixes in.

## Pages

- [debugging.md](debugging.md): task-driven troubleshooting workflows.
- [observability.md](observability.md): signal model and triage approach.
- [logging.md](logging.md): what/why/how to log.
- [testing.md](testing.md): behavior-first testing strategy and commands.
